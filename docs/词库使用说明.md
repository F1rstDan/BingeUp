## 文件位置

正式运行包：

```text
public/dictionaries/
```

主要文件：

- `manifest.json`：schema、版本、文件哈希和数量。
- `words.json`：有效词条。
- `decks.json`：三个词库及成员关系。
- `questions.json`：固定题组。
- `legacy-registry.json`：旧 ID 到有效词的唯一去向。
- `source-metadata.json`：内容与 IPA 来源。
- `LICENSE.txt` 和 `licenses/`：许可文本。

生成的候选包：

```text
data/dictionary-rebuild/staging/
```

生成依据和批次记录：

```text
data/dictionary-rebuild/
```

旧包、切换记录和回滚历史在 `data/dictionary-rebuild/archive/`。

构建后，词库进入：

```text
.output/chrome-mv3/dictionaries/
.output/edge-mv3/dictionaries/
```

## 构建和安装

```bash
npm install
npm run build
npm run build:edge
```

在 Chrome 打开 `chrome://extensions/`，在 Edge 打开 `edge://extensions/`。启用开发者模式，选择“加载已解压的扩展程序”，然后选择对应的 `.output/*-mv3` 目录。

词库改动后，重新加载扩展或重启后台服务。后台会重新校验 manifest 和文件哈希。

## 重建和切换

不要直接手工修改 `public/dictionaries/`。使用流水线生成和切换。

```bash
npm run dictionary:check
npm run dictionary:build
npm run dictionary:switch
npm run dictionary:verify-package
npm run build
npm run build:edge
```

`dictionary:build` 先把已验证批次合并到 `data/dictionary-rebuild/staging/`。`dictionary:switch` 再替换正式运行包。只有全部批次通过检查后才能切换。

批次状态和处理命令的详细记录在归档文档 `docs/.archive/dictionary-pipeline.md`。当前入口是本页和仓库脚本。

## 用户数据导入

设置页的“数据管理 → 导入数据”只恢复用户数据。用户数据包括学习进度、设置、网站配置、会话和行为事件。内置词库不进入用户备份。

扩展没有单独的“导入任意词典”入口。内置词库随扩展包加载，不从网络下载。

恢复 v1 或 v2 备份时，导入操作完整替换当前用户数据。导入失败时，原数据保持不变。

## 回滚

回滚前先导出当前 v2 用户数据。

```bash
npm run dictionary:rollback -- --dry-run
npm run dictionary:rollback
npm run build
npm run build:edge
```

回滚完成后，重新加载扩展，再导入刚才导出的 v2 备份。
